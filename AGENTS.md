# Строгие правила данных

Эти правила обязательны для людей и агентов в этом репозитории.

## Что нельзя коммитить и пушить

Не добавлять в git и не отправлять на GitHub никакие рабочие значения и выгрузки:

- сотрудники и любые списки пользователей;
- алиасы;
- организации, включая реальный идентификатор организации;
- федерация;
- группы;
- ключи, токены, client secret, пароли и другие секреты;
- прочие переменные окружения, локальные конфиги и ответы API.

Запрет не зависит от расширения файла. CSV, JSON, логи и примеры с реальными значениями тоже нельзя.

## Где хранить настройки

- Обычные переменные — только в локальном `.env`. Файл не коммитится. В репозитории допустим `.env.example` с пустыми или явно фиктивными значениями.
- Секреты — только в переменных окружения процесса (`ENV`). Их нельзя записывать в `.env`, `y360c.json`, исходники, тесты, логи и аргументы, которые сохраняются в репозитории.
- Токен доступа передаётся через `Y360_TOKEN`. Команда `init` не печатает значение токена.

`y360c.json` в домашнем каталоге — локальный файл upstream-CLI. Его нельзя копировать в репозиторий. Новые изменения не должны сохранять секрет в этот файл.

## Разработка

Язык проекта — Go. Публичный форк остаётся отдельным репозиторием под GPL-3.0 и не копируется в другие проектные репозитории вместе с рабочими данными.
